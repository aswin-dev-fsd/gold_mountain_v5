# MASTER - Gold Mountain Wellness Resort

## 0. Purpose

Build a premium, international-facing website for Gold Mountain Wellness Resort in Tiruvannamalai, Tamil Nadu, India.

The website must create desire, explain the experience clearly, reduce uncertainty, build trust, and guide visitors toward a personal enquiry.

## 1. Authoritative positioning

Gold Mountain is a **wellness resort**.

It is not:
- an Ayurveda clinic
- an Ayurveda treatment centre
- an Ayurveda-only retreat
- a generic hotel website
- a spiritual organization
- a medical website
- a generic Indian resort booking website
- a generic wellness template

The resort is the destination and the environment for the stay. Wellness is the strongest proposition, not the entire identity.

The experience brings together:

`RESORT + NATURE + WELLNESS + FOOD + LOCATION + EXPERIENCE + STAY`

Ayurveda and traditional therapies are important parts of wellness, but they must not visually or strategically dominate the entire site.

## 2. Core narrative

The source strategy's core idea is healing the body and mind through traditional therapy and healthy food amidst nature in the presence of Arunachala.

Use the idea naturally rather than repeating a single sentence throughout the site.

Primary narrative:

- Wellness is the reason to come.
- Arunachala is a defining reason the place is special.
- The resort, food, nature and experiences make the stay meaningful.
- The guest should feel guided from curiosity to confidence to enquiry.

The strategic website story is:

**Come for wellness. Stay for the experience.**

Treat this as a strategic principle, not a requirement to repeat the phrase everywhere.

## 3. Final homepage sequence

This is the authoritative homepage sequence:

`Hero -> Wellness -> Arunachala / Location -> Food -> Resort -> Experience -> Stay -> Trust -> Blog -> Final Enquiry CTA`

Arunachala may also appear subtly in the hero. The dedicated location section comes after the Resort section only if the page implementation needs the location story there; otherwise follow the sequence above exactly. Do not invent an additional standalone section simply to satisfy the architecture.

## 4. Navigation

Primary navigation:

- Home
- Wellness
- Stay
- Experience
- About
- Blog
- Contact

Do not use Gallery as a primary navigation item.

### Header CTA

Use:
- `Enquire` as the header CTA
- a WhatsApp action/icon that is clearly accessible

Do not use `Book Now`.

### Contextual CTAs

Use concise, relevant actions such as:
- Explore Wellness
- Explore the Resort
- Explore the Experience
- Plan Your Stay
- Discover Dining
- Learn More

### Final conversion CTA

Primary: `WhatsApp Us`
Secondary: `Send an Enquiry`

Email must remain clearly available.

WhatsApp is the primary enquiry route; this is not a live hotel booking engine.

## 5. Target audience

Primary:
- international guests seeking a peaceful wellness-oriented stay in India
- visitors interested in nature, Ayurveda, traditional wellness, healthy food and meaningful travel
- guests who need context about Tiruvannamalai, Arunachala and Indian wellness practices

Secondary:
- Indian guests seeking wellness stays, peaceful accommodation, Ayurveda, nature, longer stays and healthy food

Write in clear international English. Explain unfamiliar terms simply and respectfully.

## 6. Content priority

Treat the following as strategic weighting, not literal page or screen area:

- Wellness: 50%
- Location / Nature: 20%
- Food / Nourishment: 15%
- Resort / Stay: 10%
- Brand story: 5%

Wellness includes traditional therapies, Ayurveda, yoga, meditation, food, nature, lifestyle, rest and mind-body wellbeing.

Do not interpret 50% as permission to make half the website Ayurveda content.

## 7. International UX principle

Every important page should answer questions an international visitor may already have:

- Why should I come here?
- What will I experience?
- What is the place actually like?
- What is wellness here?
- What should I know about Ayurveda?
- Where is it?
- How long should I stay?
- What does accommodation look like?
- How does the enquiry process work?

Reduce uncertainty before asking for conversion.

## 8. Visual direction

The site should feel:

- minimal
- luxurious
- calm
- editorial
- natural
- premium
- international
- warm
- timeless

Design language:
- large photography
- generous whitespace
- strong typography
- editorial image/text compositions
- asymmetry where useful
- thin dividers
- restrained decorative lines and natural motifs
- spacious layouts
- subtle hover states
- minimal UI chrome

Avoid:
- glassmorphism
- neon
- excessive shadows
- excessive rounded cards
- heavy gradients
- giant icon grids
- crowded layouts
- generic SaaS UI
- futuristic UI
- generic spa-template styling
- excessive gold
- excessive animation

## 9. Motion

Use **minimal motion**.

Allowed:
- subtle reveal on scroll
- gentle image reveal
- restrained fade/slide transitions
- tasteful hover feedback
- smooth navigation transitions where they do not delay interaction

Avoid:
- heavy parallax
- scroll-jacking
- constant floating motion
- animated background effects
- cinematic sequences that hurt performance
- motion used only for decoration

Respect reduced-motion preferences.

## 10. Brand typography

The supplied Brand Identity document specifies:

### Primary
`Outfit (Garet Alf)`

Use for:
- brand name
- main headings
- section titles
- navigation
- buttons
- key statements
- primary UI

### Secondary
`The Seasons`

Use selectively for:
- supporting headings
- short editorial statements
- descriptors

The previous `Master prompt.txt` referred to `Garet Sans`. The Brand Identity file is more specific and shows **Outfit (Garet Alf)** as the primary typeface. Use the Brand Identity specification as the final typography authority.

Do not add random fonts.

If the exact approved font files are not yet available, use a controlled fallback temporarily and structure the font system so the approved font can be inserted later without redesigning components.

## 11. Brand colours

Use the supplied Brand Identity palette:

- Forest Green: `#214D33`
- Gold: `#C49A3A`
- Deep Red: `#8F2D24`
- Warm Ivory: `#F7F3EA`

Overall brand balance:
- 50% Warm Ivory
- 25% Forest Green
- 15% Gold
- 10% Deep Red

These are overall brand-experience proportions, not a component recipe.

Preferred application:
- Warm Ivory: primary background and negative space
- Forest Green: grounding colour, navigation, major brand areas and selected buttons
- Gold: restrained premium accent, logo/lines/headings/details
- Deep Red: very small supporting accents only

Do not put all colours into every card or component.

## 12. Logo

Use the supplied approved Gold Mountain logo assets.

Do not:
- redraw the logo
- distort it
- stretch it
- add effects
- add extra symbols inside it
- place it against busy imagery without sufficient clear space

Respect the supplied logo clear-space guidance.

## 13. Imagery

Photography should feel:
- warm
- natural
- quiet
- authentic
- premium
- human
- believable

Prioritise actual Gold Mountain photography when available.

Until the full asset library is ready:
- use the supplied assets where useful
- use carefully selected high-quality online imagery when required
- record every temporary external image in the asset registry
- replace temporary imagery later according to `REPLACEMENTS.md`

Never use the Buddha image from the currently supplied four-image screenshot set unless later explicitly approved. Use another suitable image instead.

## 14. Content integrity

Never invent or imply unverified facts.

Do not fabricate:
- room types
- room names
- pricing
- live availability
- package availability
- package inclusions
- testimonials
- review scores
- awards
- certifications
- medical claims
- doctors or practitioners
- founder achievements
- guest numbers
- distances
- facilities
- amenities
- years of operation
- contact numbers
- email addresses
- social handles
- experience details

Temporary development content is allowed for visual completion, but it must be tracked in `REPLACEMENTS.md` and clearly treated as temporary internally.

## 15. Enquiry model

The site is enquiry-led.

Do not build:
- fake availability
- fake room inventory
- fake booking confirmations
- fake payment flow
- a fake availability calendar
- a pretend real-time reservation engine

The team confirms availability and final pricing personally.

## 16. Pricing

Base currency: INR.

When confirmed prices exist, USD and EUR may be shown as clearly labelled indicative conversions.

Do not invent exchange-rate numbers or package prices.

When required data is absent, use internal placeholder tracking such as `PRICE_TO_BE_PROVIDED` rather than silently fabricating a number.

## 17. Technical foundation

Preferred stack:

- Next.js
- React
- TypeScript
- App Router
- Tailwind CSS with a small controlled custom CSS layer where it improves the design system
- Next.js optimized images

Use the latest stable production-supported Next.js release available at implementation time; do not use Canary/experimental releases for the production baseline. Pin installed versions in the lockfile after project initialization.

At the time this document was normalized, Next.js 16.3.x was the Active LTS line; verify the current supported patch before initialization.

Next.js officially supports App Router and common styling approaches including Tailwind and CSS Modules, and its `next/image` component provides image optimization/lazy loading behaviour. See the official references in the project notes if needed.

Do not add packages unless the current task has a clear reason for them.

## 18. Component architecture

Use reusable sections/components with page-specific composition.

Avoid both extremes:
- one giant page component
- unnecessary over-abstraction

Create a small, coherent design system and reuse it everywhere.

## 19. Responsive behaviour

Design responsively from the first component.

Do not merely shrink desktop.

Mobile may need different composition, ordering or cropping while preserving the same hierarchy and narrative.

Verify mobile, tablet and desktop at every major stage.

## 20. Accessibility

Build with semantic HTML and WCAG-conscious patterns from the beginning:
- logical headings
- keyboard access
- visible focus states
- meaningful alt text
- accessible forms
- labelled controls
- adequate contrast
- reduced-motion support
- no interaction that depends only on hover

## 21. SEO

Build technical SEO from the beginning:
- page metadata
- meaningful titles/descriptions
- canonical strategy where applicable
- Open Graph metadata
- semantic headings
- clean URLs
- crawlable content
- descriptive image alt text
- structured internal linking
- sitemap/robots when appropriate

Do not keyword-stuff copy.

## 22. Performance

Performance is an acceptance criterion.

Optimise for:
- Core Web Vitals
- Lighthouse
- image payload size
- responsive image sizing
- font loading
- unnecessary JavaScript
- third-party scripts
- cumulative layout shift
- long initial tasks

Prefer server components by default and add client components only where interactivity requires them.

## 23. Dependency rule

A dependency may be added only if:
1. the current implementation genuinely needs it,
2. the package is actively maintained or otherwise justified,
3. a built-in/browser/Next.js solution is not sufficient,
4. adding it will not create avoidable performance or maintenance cost.

## 24. Antigravity execution protocol

For every major task:

1. Inspect the relevant repository, dependencies, current implementation and assets.
2. Read the applicable documentation in this folder.
3. State a short implementation plan.
4. List the files expected to change.
5. Implement the smallest coherent step.
6. Run the appropriate development/build/type/lint checks.
7. Visually inspect the affected routes in desktop and mobile layouts.
8. Fix issues before continuing.
9. Update documentation or `REPLACEMENTS.md` when temporary material or a decision changes.
10. Report what changed and what remains.
11. Create a Git checkpoint for completed major stages.
12. Stop at the stage boundary unless the next stage is explicitly part of the current task.

Do not improvise a different design direction during implementation.

## 25. Handling ambiguity/conflict

When a lower-level instruction conflicts with a higher-level one:
- follow the hierarchy
- do not silently invent a compromise
- record unresolved issues in `DECISIONS.md` or the appropriate replacement/verification section

Do not block the entire build for minor uncertainty; use a documented temporary choice when it is safe to do so.

## 26. Definition of success

The final website should feel like:

**A premium wellness resort in nature.**

It must not feel like:
- a wellness SaaS product
- a spa template
- an Ayurveda clinic
- a generic hotel booking template
- a futuristic glassmorphism website
- an AI-generated collection of unrelated sections
